# 演習 4: 修正版の動作確認と総括

| [← 前の手順](./3-copilot-fix.md) |  |
|:--|--:|

このセクションでは、修正されたアプリケーションを起動し、SQL Injection攻撃が防げることを確認します。また、ハンズオン全体を振り返り、学習成果を総括します。

## シナリオ

前の演習でGitHub Copilotを使用してセキュリティ修正を完了しました。最終演習では修正効果を検証し、ハンズオン全体を総括します。

この演習では以下を達成します：
- 修正版アプリケーションでの正常機能の動作確認
- SQL Injection攻撃が防げることの検証
- 修正前後の動作比較による効果の実感
- ハンズオン全体の学習成果の総括

これにより、GitHub Copilotを活用したセキュア開発の有効性を実感できます。

## 必須 1. 修正版アプリケーションの起動

### 1.1 既存プロセスの停止

VS Codeターミナルで実行中のアプリケーションを停止します。

1. VS Codeのターミナルがアクティブであることを確認します
2. **`Ctrl + C`** を押してアプリケーションプロセスを終了します
3. プロセスが停止し、コマンドプロンプトが表示されることを確認します

### 1.2 修正版の起動

同じディレクトリ（`demos`フォルダー）で修正版を起動します：

```powershell
python sqlinject_python.py
```

アプリケーションが正常に起動することを確認します。

## 必須 2. 正常機能の動作確認

### 2.1 正常な検索機能のテスト

以下のURLにアクセスします：
```
http://localhost:8080/search?name=Apple
```

**期待される結果：**
- Appleを含む商品のみが表示される
- 修正前と同様に正常な検索が機能する

### 2.2 別の商品での確認

別の商品でも正常動作を確認します：
```
http://localhost:8080/search?name=Samsung
```

Samsung関連の商品のみが適切に表示されることを確認します。

## 必須 3. セキュリティ修正の効果確認

### 3.1 SQL Injection攻撃の実行

修正前に成功した攻撃を再度実行します：
```
http://localhost:8080/search?name=' OR 1=1 --
```

**期待される結果：**
- ? **攻撃が失敗する**（検索結果なし、またはエラー）
- ? **全件データが表示されない**
- ? **修正が有効に機能している**

### 3.2 追加の攻撃パターンのテスト

他の攻撃パターンも試してみます：
```
http://localhost:8080/search?name=' UNION SELECT * FROM products --
```

これらの攻撃も防がれることを確認します。

### 3.3 修正効果の詳細確認

**修正前の動作（脆弱）:**
- 攻撃により全41件の商品が漏洩
- データベース全体への不正アクセス可能

**修正後の動作（安全）:**
- 攻撃が無効化される
- プリペアードステートメントにより安全なクエリ実行

## 参考 4. コードレビューと理解の深化

### 4.1 修正されたコードの再確認

修正されたコードをもう一度確認してみましょう：

**Python版の修正後:**
```python
query = "SELECT * FROM products WHERE name LIKE ?"
cursor.execute(query, (f'%{product_name}%',))
# パラメータ化クエリによる安全な実行
```

### 4.2 セキュリティ強化のポイント

1. **パラメータ化**: ユーザー入力とSQLクエリの完全分離
2. **自動エスケープ**: データベースエンジンによる危険文字の無害化
3. **クエリ構造保護**: SQL文の構造改変の防止

## オプション 5. さらなるセキュリティテスト

### 5.1 エッジケースのテスト

以下のようなエッジケースも確認してみましょう：

2. **空の検索文字列**:

## トラブルシューティング

### 問題が発生した場合

1. **攻撃がまだ成功してしまう場合**:
   - 修正が正しく適用されているかコードを再確認
   - ファイルが保存されているか確認
   - アプリケーションの再起動を確実に実行

2. **正常な検索が機能しない場合**:
   - プリペアードステートメントの記法を確認
   - パラメータの渡し方を再確認
   - エラーメッセージをターミナルで確認

3. **予期しない動作の場合**:
   - 修正前のコードと修正後のコードを比較
   - 必要に応じてGitHub Copilotに再度修正を依頼
